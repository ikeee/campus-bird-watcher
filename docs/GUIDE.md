## 一、准备工作

在开始部署之前，请确认以下材料已准备齐全。

### 1.1 硬件与网络

| 项目 | 要求 | 说明 |
|------|------|------|
| 群晖 NAS | DSM 7.0 或以上 | 已安装 Container Manager 套件 |
| 内存 | 建议 2 GB 以上可用 | MySQL + Node.js 合计约占 400 MB |
| 存储空间 | 建议预留 20 GB | 每张鸟类图片约 200–500 KB |
| 网络 | 内网可访问外网 | 用于调用 AI API（萤石云 API 也需要） |
| 萤石云摄像头 | 任意型号 | 已安装在鸟屋附近，角度对准取食区 |

### 1.2 账号与 API Key

在开始之前，请提前注册以下账号并获取对应的 Key：

**萤石云开放平台（必须）**

1. 访问 [open.ys7.com](https://open.ys7.com) 并注册账号
2. 进入「开发者服务」→「我的应用」→ 创建应用
3. 记录 **AppKey** 和 **AppSecret**（后续填入系统）
4. 在萤石云 App 或摄像头背面查找**设备序列号**

**AI 视觉模型 API（至少选一个）**

推荐使用 DeepSeek，性价比高且对中文鸟类名称识别效果好：

- **DeepSeek**：访问 [platform.deepseek.com](https://platform.deepseek.com) → API Keys → 创建
- **OpenAI**：访问 [platform.openai.com](https://platform.openai.com) → API Keys → 创建
- **Gemini**：访问 [aistudio.google.com](https://aistudio.google.com) → Get API Key

## 二、群晖 NAS 部署

### 2.1 通过 SSH 连接群晖

在群晖 DSM 中启用 SSH：控制面板 → 终端机和 SNMP → 启动 SSH 功能。

然后在电脑终端连接：

```bash
ssh admin@192.168.1.100   # 替换为你的群晖 IP
```

### 2.2 安装 Container Manager

如果尚未安装，请在 DSM → 套件中心 → 搜索「Container Manager」并安装。

### 2.3 创建数据目录

```bash
# 创建项目目录和数据存储目录
mkdir -p /volume1/docker/birdwatch/app
mkdir -p /volume1/docker/birdwatch/mysql
mkdir -p /volume1/docker/birdwatch/uploads

# 设置目录权限
chmod 755 /volume1/docker/birdwatch/uploads
```

### 2.4 下载项目代码

**方法一：通过 Git（推荐）**

```bash
# 安装 Git（如未安装）：DSM → 套件中心 → 搜索 Git Server
cd /volume1/docker/birdwatch
git clone https://github.com/your-repo/campus-bird-watcher.git app
cd app
```

**方法二：通过 File Station 上传**

将项目压缩包上传至群晖，解压到 `/volume1/docker/birdwatch/app/`。

### 2.5 配置环境变量

```bash
cd /volume1/docker/birdwatch/app
nano .env
```

将以下内容粘贴并修改（每行说明已注释）：

```bash
# ── 数据库密码 ────────────────────────────────────────────
# MySQL root 密码（仅 Docker 内部使用，不对外暴露）
DB_ROOT_PASSWORD=MyRootPass2024!

# 应用连接数据库的密码（与 root 密码不同）
DB_PASSWORD=MyBirdWatchPass2024!

# ── 存储路径 ──────────────────────────────────────────────
# 数据库文件存储路径（群晖绝对路径）
DB_HOST_PATH=/volume1/docker/birdwatch/mysql

# 鸟类图片存储路径（群晖绝对路径）
UPLOADS_HOST_PATH=/volume1/docker/birdwatch/uploads

# ── 安全密钥 ──────────────────────────────────────────────
# JWT 签名密钥（随机字符串，建议 32 位以上）
# 可用此命令生成：openssl rand -hex 32
JWT_SECRET=请替换为随机字符串

# ── 管理员账号 ────────────────────────────────────────────
# 初始管理员密码（首次登录后请立即修改）
ADMIN_INIT_PASSWORD=YourAdminPassword2024

# ── AI 模型（可选，也可在管理后台配置）────────────────────
DEFAULT_AI_PROVIDER=deepseek
DEFAULT_AI_API_KEY=sk-your-deepseek-api-key
DEFAULT_AI_BASE_URL=https://api.deepseek.com
DEFAULT_AI_MODEL=deepseek-chat
```

> **安全提示**：`.env` 文件包含敏感信息，请勿分享或提交到 Git 仓库。

### 2.6 启动服务

```bash
cd /volume1/docker/birdwatch/app

# 首次启动（构建镜像约需 3–5 分钟）
docker compose up -d --build

# 实时查看启动日志
docker compose logs -f app
```

看到以下日志说明启动成功：

```
campus-bird-watcher  | Server running on http://localhost:3000/
```

### 2.7 验证访问

在局域网内任意设备的浏览器中访问：

```
http://192.168.1.100:3000
```

（将 `192.168.1.100` 替换为你的群晖 IP 地址）

### 2.8 设置开机自启

Container Manager 中的容器默认设置为 `unless-stopped`，群晖重启后会自动恢复运行。如需确认，可在 DSM → Container Manager → 容器 中查看状态。

## 四、配置萤石云摄像头

### 4.1 获取萤石云凭证

登录 [萤石云开放平台](https://open.ys7.com)，进入「开发者服务」→「我的应用」，记录以下信息：

| 字段 | 位置 | 示例 |
|------|------|------|
| AppKey | 应用详情页 | `at3bfxxxxx` |
| AppSecret | 应用详情页 | `7e8f9xxxxx` |
| 设备序列号 | 摄像头背面贴纸 | `ABCDEF123456` |

### 4.2 添加摄像头

1. 进入**管理后台**（顶部导航栏）
2. 点击「添加摄像头」按钮
3. 填写以下信息：

| 字段 | 说明 | 建议值 |
|------|------|--------|
| 摄像头名称 | 自定义，如"鸟屋1号" | 鸟屋摄像头 |
| AppKey | 萤石云开放平台获取 | — |
| AppSecret | 萤石云开放平台获取 | — |
| 设备序列号 | 摄像头背面 | — |
| 通道号 | 通常为 1，多通道摄像头按实际填写 | 1 |
| 轮询间隔 | 抓拍频率（毫秒），建议 30 秒以上 | 30000 |

4. 点击「保存」

### 4.3 启动监控

摄像头配置保存后，点击该摄像头卡片上的「启动」按钮。系统将开始按设定间隔自动抓拍并识别。

> **关于轮询间隔**：萤石云免费账号对抓拍 API 有调用频率限制，建议将间隔设置为 **30000ms（30 秒）** 或以上，避免触发 `code: 10028` 超限错误。如需更高频率，请在萤石云开放平台申请提升配额。

### 4.4 测试抓拍

启动监控后，等待一个轮询周期（如 30 秒），查看首页是否出现新的识别记录。如果摄像头前有鸟类活动，应能看到识别结果卡片。

## 五、配置 AI 识鸟模型

### 5.1 进入 AI 模型管理

在管理后台页面，点击「管理模型」按钮，进入 AI 模型配置页面。

### 5.2 添加模型配置

点击「添加模型配置」，按以下说明填写：

**DeepSeek（推荐）**

```
提供商：DeepSeek
API Key：sk-xxxxxxxx（从 platform.deepseek.com 获取）
Base URL：https://api.deepseek.com
模型型号：deepseek-chat
```

**OpenAI**

```
提供商：OpenAI
API Key：sk-xxxxxxxx（从 platform.openai.com 获取）
Base URL：https://api.openai.com
模型型号：gpt-4o-mini（或 gpt-4o，精度更高但费用较贵）
```

**Ollama 本地模型（完全离线）**

如果学校有 GPU 服务器，可以在服务器上安装 [Ollama](https://ollama.ai) 并运行 `llava` 模型，实现完全不依赖外网的本地识别：

```
提供商：Ollama（本地）
API Key：（留空）
Base URL：http://192.168.1.200:11434（替换为 Ollama 服务器的内网 IP）
模型型号：llava
```

### 5.3 测试连接

填写完成后，点击「测试识别」按钮，系统会使用一张示例图片测试 API 连通性和识别效果。测试通过后，点击「激活」使其生效。

> **注意**：同一时间只有一个模型配置处于激活状态。切换模型后，下一次抓拍将自动使用新的模型。

## 六、置信度阈值与人工复核

### 6.1 理解置信度

AI 模型在识别鸟类时会给出一个**置信度**（0%–100%），表示对识别结果的把握程度。置信度越高，识别越可靠。

- **90% 以上**：非常确定，直接自动通过
- **70%–90%**：较为确定，建议自动通过
- **50%–70%**：不太确定，建议进入复核队列
- **50% 以下**：不确定，建议拒绝或人工确认

### 6.2 设置阈值

在管理后台的「识别置信度阈值」面板中，拖动滑块设置阈值。系统提供 50%、60%、70%、75%、80%、90% 六个快捷按钮。

- 高于阈值的识别结果：自动标记为「已通过」，直接展示在首页和识别记录
- 低于阈值的识别结果：进入「待复核」队列，等待管理员确认

### 6.3 人工复核

点击顶部导航栏「管理后台」旁的橙色数字角标，或直接访问「待复核」页面。

每条待复核记录显示：抓拍图片、AI 识别的品种名、置信度、抓拍时间。管理员可以：

- **通过**：确认识别正确，记录进入正式展示
- **拒绝**：识别错误或图片中无鸟，记录不展示
- **批量操作**：勾选多条记录后批量通过或拒绝

## 七、日常使用说明

### 7.1 首页（实时监控）

首页展示今日识别总数、鸟类品种数、最新到访品种，以及扇形展开的最新鸟类图片。页面每 30 秒自动刷新数据。

### 7.2 识别记录

识别记录页以卡片形式展示所有已通过的识别记录，支持：

- 按时间倒序排列
- 点击卡片查看详情（含学名、分类目科、置信度进度条、原始图片）
- 从详情弹窗直接跳转到该鸟种的百科页面

### 7.3 历史统计

历史统计页提供三种数据视图：

- **今日按小时分布**：柱状图展示一天中各小时段的鸟类到访频次，可了解鸟类活跃时间规律
- **品种分布**：饼图展示各品种的占比
- **品种排行**：按到访次数排列的品种列表，快速了解最常见的校园鸟类

### 7.4 鸟类百科

每当系统识别到一种新的鸟类，会自动触发 AI 生成该鸟种的百科内容，包含：

| 知识卡片 | 内容 |
|---------|------|
| 形态特征 | 体型、羽色、嘴形等外观描述 |
| 生活习性 | 行为模式、活动规律 |
| 食性 | 主要食物来源 |
| 分布地区 | 全球及中国分布范围 |
| 栖息地 | 偏好的生态环境 |
| 繁殖 | 繁殖季节、筑巢习性 |
| 鸣声 | 叫声特征描述 + Xeno-canto 试听链接 |
| 保护状态 | IUCN 保护等级 |
| 校园观察建议 | 在校园中观察该鸟种的最佳时机和方法 |

百科内容可在详情页由管理员手动触发重新生成（如内容有误或需要更新）。

## 八、鸟类百科功能

### 8.1 自动生成

系统在以下情况自动生成百科内容：

- 首次识别到某种鸟类时（自动触发）
- 管理员在百科详情页点击「重新生成」时

生成过程通常需要 5–15 秒，生成完成后页面自动刷新显示内容。

### 8.2 多图展示

百科详情页的图片轮播展示该鸟种历次被识别的照片，每张图片标注拍摄时间和置信度，可直观了解该鸟种在校园中的真实样貌。

### 8.3 鸣声试听

百科详情页提供 [Xeno-canto](https://xeno-canto.org) 和 [eBird](https://ebird.org) 的外链，点击可跳转到专业鸟类数据库试听该鸟种的鸣声录音，适合生物课教学使用。

## 九、运维与备份

### 9.1 常用命令

```bash
# 查看应用运行状态
docker compose ps

# 查看实时日志
docker compose logs -f app

# 重启应用（不重建镜像）
docker compose restart app

# 停止所有服务
docker compose down

# 更新应用（拉取新代码后重建）
git pull
docker compose up -d --build app
```

### 9.2 数据备份

建议每周备份一次数据库和图片：

```bash
# 备份数据库
docker exec campus-bird-watcher-db \
  mysqldump -u birdwatch -p${DB_PASSWORD} birdwatch \
  > /volume1/backup/birdwatch_$(date +%Y%m%d).sql

# 备份图片（同步到备份目录）
rsync -av /volume1/docker/birdwatch/uploads/ \
  /volume1/backup/birdwatch-uploads/
```

也可以在群晖 **Hyper Backup** 中配置定时备份任务，将以下目录纳入备份范围：

- `/volume1/docker/birdwatch/mysql/`
- `/volume1/docker/birdwatch/uploads/`

### 9.3 查看图片存储占用

```bash
du -sh /volume1/docker/birdwatch/uploads/
```

如存储空间紧张，可以在识别记录页面删除旧记录，对应图片文件也会一并清理。

## 十、常见问题

**Q：访问 3000 端口提示无法连接**

检查群晖防火墙是否放行了 3000 端口：DSM → 控制面板 → 安全性 → 防火墙 → 编辑规则，添加允许 TCP 3000 端口的规则。

---

**Q：萤石云报错"抓图接口调用次数超限"（code: 10028）**

这是萤石云免费账号的 API 调用频率限制。解决方法：

1. 在管理后台将该摄像头的轮询间隔调大至 **60000ms（1分钟）** 以上
2. 或登录萤石云开放平台申请提升 API 调用配额

---

**Q：AI 识别结果不准确，经常识别错误**

可以尝试以下方法提升准确率：

1. 在 AI 模型管理页切换到更强的模型（如 `gpt-4o` 或 `gemini-2.5-pro`）
2. 调整摄像头角度，确保鸟类在画面中占据较大比例
3. 降低置信度阈值，将更多结果送入人工复核队列，由老师确认

---

**Q：图片无法显示，显示为破图**

检查图片存储目录权限：

```bash
chmod -R 755 /volume1/docker/birdwatch/uploads/
```

---

**Q：数据库连接失败，应用无法启动**

常见原因：

1. `.env` 中的 `DB_PASSWORD` 包含特殊字符（如 `@`、`#`），请用引号包裹或更换密码
2. 数据库目录权限不足：`chmod 755 /volume1/docker/birdwatch/mysql/`
3. 等待数据库初始化完成（首次启动约需 30 秒）

---

**Q：如何在不同班级之间共享观鸟数据？**

系统本身支持多用户访问，局域网内所有设备都可以直接访问 `http://群晖IP:3000` 查看识别记录和百科内容，无需登录。只有管理后台操作（配置摄像头、审核记录）需要管理员权限。

---

**Q：如何更换域名，让师生通过域名访问？**

可以在群晖 DSM → 控制面板 → 登录门户 → 反向代理中，将内网域名（如 `birds.school.local`）代理到 `localhost:3000`，然后在学校 DNS 服务器中添加对应解析记录。
